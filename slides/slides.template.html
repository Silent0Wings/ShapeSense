ShapeSense: an LLM-assisted pipeline that recognizes 2D shapes

Task: classify a 64x64 drawing into one of 10 shapes (circle, ellipse, triangle, square, rectangle, pentagon, hexagon, octagon, star, diamond). Metric: macro F1 on a sealed test split of 2,776 images.

Dataset: 18,000 images from 4 public sources

  • Quick, Draw! doodles (CC BY 4.0)
  • Kaggle reevald printed shapes (CC0)
  • Mendeley El Korchi rendered shapes (CC BY 4.0)
  • GitHub frobertpixto hand-drawn shapes (CC BY 4.0)

No source covers all 10 classes; together they do. Split 12,405 / 2,819 / 2,776, grouped by near-duplicates.

Stage by stage

Where the LLMs helped, and where we corrected them

Every prompt and response is in prompts/<stage>/. 101 logged decisions: the LLM proposed 52, assisted on 27 more, and the team caught 8 problems itself.

LLM helped

  • DataFour sources that together cover all 10 classes; four candidates rejected for license or coverage
  • CleaningFound that most Quick, Draw! "diamonds" are gems, not rhombi (recall 59%); excluded by rule before any test read
  • TransformationRotation of ±180° hurt square, rectangle and diamond; searched range ±20°, capped at ±10° for those three
  • TestingGemini's audit found test counts never checked against the noise bands; Stage 5 now refuses to run if they differ

Team corrected the LLM

  • ModelingThe first CNN saw only 22 px of a 64 px shape; moved from 3 to 4 conv blocks
  • SpeedAn outside report said to convert pixels on the GPU; we measured first: 126 of 256 values round differently, so we used a lookup table
  • TestingTwo pre-registered hypotheses failed (B vs A1 -0.36, CI [-1.17, 0.41]; A2 vs A0 +0.06, CI [-0.69, 0.83]); reported as failed, not reframed
  • RecordsEvery LLM claim that the records could not back is marked "not established"

Two-LLM comparison

Working with both models fixed 11 problems one model alone missed

Claude built most of the pipeline. Gemini 4 Neon, with web search on, audited it claim by claim; the team gave each claim a verdict.

Where they agreed and differed

  • Quick, Draw! diamonds: Gemini proposed the exclusion rule; Claude inspected the drawings and measured the damage (59% recall)
  • Tuning: Gemini proposed the per-arm search of augmentation, generator and hyperparameters (110 trials); both mediated between the team's views
  • On direct prediction the two agreed on 96% of 200 images and made the same two kinds of error

Did both help?

  • Yes for correctness and robustness: the audit's fixes are in the final pipeline
  • Not for clean test F1: the fixes changed checks and reporting, not the model's score

Pipeline vs. direct LLM prediction

The trained CNN beats both LLMs on the same 200 test images

200 test images (20 per class), shown blind to each LLM with 50 labeled training examples. Same images, same metric.

{{DIRECT_BARS}}

Why the gap

Both LLMs make the same errors: circle called ellipse (4 each) and hexagon called octagon (4 each). These turn on axis ratio and corner count at 64 px, boundaries the CNN learned from 12,405 labeled images.

Where the LLMs still win

Rarely. The CNN also leads on Quick, Draw! sketches (24 of 27 against 21 of 27). The LLMs were right where the CNN was wrong on only two noisy hand-drawn shapes: an ellipse the CNN called a triangle, and a rectangle it called a diamond (Claude only).

Verification

How we checked the final results

No LLM output was trusted until a check in code or on data confirmed it.

Before any test read

  • Hypotheses pre-registered in writing
  • Test split and two fresh holdouts sealed; every read logged
  • Import-linter and contract tests stop stages reading data they should not see
  • Near-duplicates grouped so they never straddle train and test

On the results

  • 5 seeds per arm; bootstrap CIs, McNemar tests, Holm correction
  • Classical baselines (HOG + SVM 84.3) and a source-shortcut check
  • Manual QA sheets; 27-claim external audit by the second LLM
  • Browser models checked against Python, logits within 1e-4

Lessons learned

What working with two LLMs taught us

Measure before trusting

Plausible advice was wrong when unmeasured: GPU pixel conversion would have changed every result, and full rotation hurt three classes. Each claim became a test or an experiment.

Two models share blind spots

Claude and Gemini agreed on 96% of direct predictions and made the same mistakes. A second LLM is a reviewer, not an independent check; the data has to be.

Critique beats generation

The most useful Gemini output was its audit of Claude's pipeline: 11 fixes. Asking one model to attack the other's work found more than asking either to build.
