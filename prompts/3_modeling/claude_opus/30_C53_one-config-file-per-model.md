## Prompt
To see one model's full setup, you have to read the shared parts of `configs/pipeline.yaml` and then apply that arm's overrides in your head. I want a folder with one generated file per model: its network, training settings, batch mix, augmentation and generator ranges. Can you help me write the generator and a test that keeps the files in step with the shared config?

## Response
Good idea, and the important rule is that `configs/pipeline.yaml` stays the only source of truth. The per-model files are a generated view of it, so they must never be edited by hand and a test must fail the moment they disagree.

**Generator (`scripts/export_model_configs.py`).** For each arm, resolve its config with the same function the pipeline uses to apply overrides, then write `configs/models/<arm>.yaml` with a header saying it is generated and must not be edited. Compute derived values with the training code itself rather than re-deriving them: the batch counts from the trainer's batch composition, and the learned parameter count by building the model and counting. Suggested sections:

| Section | Contents |
|---|---|
| `model` | id, plain name, one line on what it trains on |
| `network` | type, input shape, block channels, operations per block, dropout, learned parameters |
| `training` | optimizer, learning rate, weight decay, schedule, batch size, steps per epoch, epochs, seeds, hold-out runs |
| `batch_mix` | images per batch by kind, and the pretraining phase if any |
| `augmentation`, `generator` | the ranges that arm actually uses, or `null` when it uses none |

Using `null` for a section the arm does not use is clearer than leaving it out: a reader of A0 sees that augmentation is off, not that it was forgotten.

**Test (`tests/studio/test_model_configs.py`).** Parametrize over the arms:
1. Each saved file equals a freshly generated one, as dictionaries, not as text.
2. Each batch mix adds up to the batch size.
3. A model without augmentation or synthetic data lists `None` for those sections.
4. Only the pretraining model has a pretraining phase.

Cautions:
- Compare loaded data, not file bytes, so YAML formatting changes do not cause false failures.
- Do not make the pipeline read these files. If it did, there would be two sources of truth.

## Validation
`tests/studio/test_model_configs.py` holds the four tests above; the first two are parametrized over the arms, giving 12 cases for five arms. Each file in `configs/models/` (`A0`, `A1`, `B`, `A2`, `P`) opens with "Generated by scripts/export_model_configs.py from configs/pipeline.yaml. Do not edit by hand."

## Our decision
Built by 40304911 with Opus assisting: `configs/models` holds one generated file per model with its network, training settings, batch mix, augmentation and generator ranges, and a test keeps them in step with the shared config. Reason recorded: a reader can see one model's whole setup in one place.

## Measured effect
No separate measurement recorded. The generated files show, for example, B at 0 / 213 / 43 (real unchanged / real augmented / synthetic) per batch of 256, A2 at 105 / 120 / 31, and P with 7 pretraining epochs of 256 synthetic images, then 0 / 256 / 0. Every model lists 242,250 learned parameters.

### Architectural Design: Single Source of Truth vs. Read-Only Materialized Views

Reading a single arm's effective hyperparameters previously required mentally merging global defaults in `configs/pipeline.yaml` with nested `arms.<id>.overrides`. Rather than splitting configuration into five writable files (which would create split-brain drift), `scripts/export_model_configs.py` generates **read-only, self-documenting YAML artifacts** (`configs/models/<arm>.yaml`) directly from `configs/pipeline.yaml` using the pipeline's own override-resolution and model-instantiation functions:

* **Schema Completeness:** Every generated file records `model` (ID, plain name, training diet summary), `network` (`[32, 64, 128, 128]`, `242,250` exact learned parameters), `training` (AdamW, `lr`, `weight_decay`, cosine schedule, `batch_size: 256`, `49` steps/epoch, `60` epochs, `5` main seeds + `3` LOSO seeds), `batch_mix` (exact integer image counts summing to `256`, plus pretraining epoch counts), and `augmentation` / `generator` ranges (`null` when disabled so inactive components are explicit rather than omitted).
* **Materialized Arm Signatures:**
  * **`B`:** `0` clean / `213` augmented / `43` synthetic (`256` total).
  * **`A2`:** `105` clean / `120` augmented / `31` synthetic (`256` total).
  * **`P`:** `7` pretraining epochs at `0 / 0 / 256` synthetic, followed by `53` epochs at `0 / 256 / 0` augmented real.
* **Drift-Detection Test Suite (`tests/studio/test_model_configs.py`):** 12 parametrized test cases verify structural dictionary equality (ignoring YAML whitespace formatting) between saved files and fresh generator output, `batch_mix` summation to `256`, explicit `None` fields for disabled transforms, and exclusive pretraining phase assignment to `P`.
