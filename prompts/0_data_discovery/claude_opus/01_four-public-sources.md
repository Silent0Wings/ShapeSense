## Prompt
> We need images of ten 2D shapes (circle, ellipse, triangle, square, rectangle, pentagon, hexagon, octagon, star, diamond). Which public datasets cover these classes, under what license, with what image style and size? Which combination covers every class?

## Response (augmented)

Short answer: no single public dataset covers all ten of your classes, but four openly licensed sources cover them together. They also give you three different visual styles (sketched, rendered, hand-drawn), which helps a classifier generalise instead of learning one renderer's quirks.

### The four sources

| Source | Classes it gives you (mapped to your taxonomy) | Format & size | License | Role |
|---|---|---|---|---|
| Google Quick, Draw! (`quickdraw`) | circle, diamond, hexagon, octagon, square, star, triangle | 7 NDJSON stroke files, 500 recognized drawings each, rasterised by you | CC BY 4.0 | Sketch style, fast human doodles |
| Kaggle reevald, Geometric Shapes Mathematics (`kaggle_reevald`) | circle, square, triangle, rectangle, diamond (from `rhombus`) | 20,000 JPG, 224x224 RGB, 8 classes x 2,500 (1,500 train / 500 val / 500 test) | CC0 | Clean rendered shapes, the only source with a `rhombus` folder |
| Mendeley El Korchi, 2D geometric shapes (`wzr2yv7r53/1`, `mendeley_elkorchi`) | circle, triangle, square, pentagon, hexagon, octagon, star | 90,000 PNG, 200x200 RGB, 9 classes x 10,000, random position, scale, rotation and colour | CC BY 4.0 | Synthetic polygons, the only source of pentagon |
| GitHub frobertpixto hand-drawn shapes (`github_handdrawn`) | ellipse, rectangle, triangle | 27,292 PNG, 70x70 RGBA, 4 classes | CC BY 4.0 (data), MIT (code) | Hand-drawn style, the only source of ellipse |

### Per-source detail

**Google Quick, Draw!**
- Format: NDJSON stroke files, not images. Each line is a JSON object with stroke coordinates.
- Rasterisation: you must render the strokes yourself to get an image. This means you control the canvas size, line width, and background colour.
- Style: fast human doodles, often incomplete or wobbly. This is the most "human" of the four sources.
- Coverage: 7 of your 10 classes. It is the only source with `octagon` and `star` in sketch style.
- Risk: the `diamond` label is ambiguous. People draw "diamond" as a gem (a rotated square with a point at the bottom) as often as a rhombus. This needs a manual check before trusting the label.
- License: CC BY 4.0, which allows redistribution with attribution.

**Kaggle reevald, Geometric Shapes Mathematics**
- Format: JPG, 224x224 RGB, pre-split into train/val/test.
- Style: clean rendered shapes, likely generated by a script with solid fills and clean edges.
- Coverage: 5 of your 10 classes. It is the only source with a `rhombus` folder, which maps to your `diamond`.
- Risk: the `rhombus` to `diamond` mapping is a definition choice, not a label match. You should document this mapping explicitly in the build script.
- License: CC0, which is the most permissive and needs no attribution.

**Mendeley El Korchi, 2D geometric shapes**
- Format: PNG, 200x200 RGB, 9 classes x 10,000 images.
- Style: synthetic polygons with random position, scale, rotation, and colour. This is the most "programmatic" of the four sources.
- Coverage: 7 of your 10 classes. It is the only source with `pentagon`.
- Extra classes to drop: `Heptagon` and `Nonagon` are in the dataset but not in your taxonomy. The live page confirms these are part of the 9 published classes. [data.mendeley](https://data.mendeley.com/datasets/wzr2yv7r53/1)
- Generator code: the dataset ships with the generator code, so you can regenerate more data if needed. [data.mendeley](https://data.mendeley.com/datasets/wzr2yv7r53/1)
- License: CC BY 4.0, which allows redistribution with attribution.

**GitHub frobertpixto hand-drawn shapes**
- Format: PNG, 70x70 RGBA, 4 classes, 27,292 images total.
- Style: hand-drawn, likely scanned or drawn with a stylus. This is the most "human" of the four sources after Quick, Draw!.
- Coverage: 3 of your 10 classes. It is the only source with `ellipse`.
- Extra class to drop: `other` is a catch-all with no matching class in your taxonomy.
- License: CC BY 4.0 for the data, MIT for the code. This split needs to be recorded separately in the source map.
- Risk: the 70x70 size is much smaller than the other sources, so upsampling will be needed in the build step.

### How they complement each other

- **circle, triangle, square:** covered by three or four sources, so these classes get style variety for free.
- **hexagon, octagon, star:** Quick, Draw! (sketch) plus El Korchi (rendered).
- **rectangle:** reevald (rendered) plus frobertpixto (hand-drawn).
- **diamond:** reevald `rhombus` plus Quick, Draw! `diamond`. Check the Quick, Draw! drawings against your definition before trusting them. People draw "diamond" as a gem as often as a rhombus.
- **ellipse:** only `github_handdrawn`. This is a **single-source class**, so the model may learn "hand-drawn style" as a cue for ellipse.
- **pentagon:** only `mendeley_elkorchi`. This is also a **single-source class**, with the same style-leak risk.

### Labels to drop, not remap

- El Korchi `Heptagon` and `Nonagon`: not in your taxonomy. The Mendeley page confirms these are part of the 9 published classes. [data.mendeley](https://data.mendeley.com/datasets/wzr2yv7r53/1)
- reevald `kite`, `trapezoid` and `parallelogram`: not in your taxonomy. Don't fold them into diamond or rectangle, because they break the definitions.
- frobertpixto `other`: a catch-all with no matching class.

### Practical notes

- All four licenses (CC0, CC BY 4.0, MIT for code) allow redistribution with attribution. Keep a source map with the origin URL of each, so the git-ignored `data_set/` folder can be re-downloaded.
- Sizes differ (70, 200, 224 px, and vector strokes). Standardise to one resolution and channel layout in the build step, and keep a `source` column, so you can measure per-source accuracy and catch the single-source shortcut.
- Counts are very unbalanced (90,000 El Korchi vs 3,500 Quick, Draw!). Cap per class and source when you build the unified set.
- The El Korchi generator code is published alongside the dataset, so you can regenerate more data if needed. [data.mendeley](https://data.mendeley.com/datasets/wzr2yv7r53/1)
- The frobertpixto 70x70 size means upsampling to 224x224 will lose detail. Consider keeping a separate low-res branch or using a smaller input size for that source.

### Risks and mitigations

| Risk | Mitigation |
|---|---|
| Single-source classes (ellipse, pentagon) learn style as a cue | Report them as known single-source classes; consider a style-ablation test |
| `diamond` label ambiguity in Quick, Draw! | Manual check of a sample of drawings before trusting the label |
| `rhombus` to `diamond` mapping is a definition choice | Document the mapping explicitly in the build script |
| Size mismatch (70 vs 200 vs 224 px) | Standardise in the build step; consider a separate low-res branch for frobertpixto |
| Class imbalance (90k El Korchi vs 3.5k Quick, Draw!) | Cap per class and source when building the unified set |
| License tracking across four sources | Keep a source map with origin URL and license per source |

**Recommendation:** use all four together: Quick, Draw!, Kaggle reevald, Mendeley El Korchi and GitHub frobertpixto. Report ellipse and pentagon as known single-source classes.

## Our decision
No single source covers all ten classes, so the sources were chosen to cover them together and to mix sketches, printed and rendered shapes. Licenses: CC BY 4.0 or CC0. Sources: Google QuickDraw, Kaggle reevald, Mendeley El Korchi, GitHub frobertpixto hand-drawn shapes.

## Measured effect
Kept. The four sources form the unified dataset (about 18,000 rows in the Phase 1 report). No macro F1 change applies to this decision.
